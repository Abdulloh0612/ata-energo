# Запуск и разработка

## Первый запуск через Docker Compose

Из корня репозитория создайте локальную конфигурацию, если её ещё нет. Команды ниже рассчитаны на Bash. В PowerShell для первого копирования подойдёт `Copy-Item .env.example .env`.

```bash
test -f .env || cp .env.example .env
```

Укажите в `.env` свой `JWT_SECRET`. Для тестового стенда с примерами клиентов включите `SEED_DEMO=true`. Параметр `DEMO_MODE=true` отдельно включает генерацию измерений. Для работы с реальными станциями установите оба параметра в `false`. Для нового рабочего экземпляра задайте собственный пароль PostgreSQL и `APP_ENV=production`. Параметры для облачных аккаунтов описаны в [руководстве по интеграциям](INTEGRATIONS.md).

```bash
docker compose up -d --build
docker compose ps
curl -fsS http://localhost:8000/api/health
```

Контейнер приложения применяет миграции, при включённом тестовом наполнении создаёт демоданные и запускает API. Ответ проверки готовности — `{"status":"ok"}`. Откройте [CRM](http://localhost:8000) или [Swagger](http://localhost:8000/swagger/index.html). На новой демонстрационной базе есть пользователи `admin / admin123` и `client1 / client123`.

| Операция | Команда или настройка |
|---|---|
| Посмотреть причину ошибки запуска | `docker compose logs --tail=100 app database` |
| Остановить стенд с сохранением базы | `docker compose down`. Данные PostgreSQL хранятся в именованном томе. |
| Применить изменение окружения приложения | `docker compose up -d app` |
| Изменить адрес доступа | В Compose порт на компьютере задаёт `APP_PORT`, по умолчанию 8000 на `127.0.0.1`. Для Swagger укажите соответствующий внешний адрес в `APP_BASE_URL`. |

## Разработка на компьютере

**Только интерфейс.** Можно оставить API работающим в Compose. Для интерфейса используйте Node.js 22, как в сборочном образе. Запустите команды из корня репозитория и откройте адрес, который напечатает Vite.

```bash
npm --prefix web ci
npm --prefix web run dev
```

Vite направляет запросы к `/api` и `/ws` на сервер на порту 8000. Для проверки сборки выполните `npm --prefix web run build`.

**Сервер без Docker.** Нужны Go 1.23 или новее, доступная PostgreSQL и утилита `migrate` из golang-migrate с поддержкой PostgreSQL. Укажите строку подключения в `.env` и экспортируйте то же значение как `DATABASE_URL` для команды миграции. В штатном Compose PostgreSQL доступна только внутри его сети. Для тестового наполнения локальной базы после миграции можно выполнить `make seed`.

```bash
migrate -database "$DATABASE_URL" -path db/migrations up
make run
```

Go-сервер отдаёт собранный интерфейс из `web/dist`. В режиме разработки интерфейс можно открыть отдельно через Vite. Команды ниже запускаются из корня проекта.

| Команда | Назначение |
|---|---|
| `make test` и `make vet` | Тесты Go и статические проверки |
| `make swagger` | Обновить спецификацию по аннотациям Go после изменения маршрутов |
| `go run ./cmd/seeddata -clients 2` | Наполнить базу разработки тестовыми пользователями, клиентами и модемами |
| `go run ./cmd/worker -once` | Разовая проверка потери связи. При обычном запуске фоновые службы работают в основном процессе. |
| `go run ./cmd/simulator -serials TEST-SN` | Отправлять тестовые пакеты в MQTT. Укажите серийный номер зарегистрированного тестового модема и включите приём MQTT. |
| `go run ./cmd/hashpass` с аргументом | Получить bcrypt-хеш для пароля CRM |
| `make agent NAME="Офис"` | Создать локального агента и получить токен |

Состав сервисов и параметры по умолчанию приведены в [Docker Compose](../docker-compose.yml) и [примере конфигурации](../.env.example).
