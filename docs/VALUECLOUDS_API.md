# Интеграция ValueClouds в AtaEnergo

Интеграция читает аккаунты, станции, устройства, телеметрию, историю и аварии
из ValueClouds. Сохранённые аккаунты и привязки модемов используют прежние
идентификаторы и не требуют повторного подключения после обновления.
Команды изменения настроек инверторов через API AtaEnergo не предоставляются.

## Структура реализации

| Файл | Ответственность |
|---|---|
| `pkg/valueclouds/client.go` | HTTPS, подпись, вход, сессия, ошибки и ограниченное обновление авторизации |
| `pkg/valueclouds/catalog.go` | Полный каталог проектов и устройств с проверкой страниц и идентификации |
| `pkg/valueclouds/measurements.go` | Типы и методы чтения измерений, параметров, паспорта и конфигурации полей |
| `pkg/valueclouds/snapshot.go` | Общий сбор и проверка актуальности показаний для CRM и фонового мониторинга |
| `pkg/valueclouds/mapper.go` | Преобразование потоков в формат телеметрии AtaEnergo |
| `pkg/valueclouds/history.go` | Разбор исторических рядов и пропусков |
| `services/telemetry.go` | Запись времени источника и пропусков ValueClouds без повторного сохранения снимка |
| `services/valueclouds.go` | Аккаунты, импорт устройств, привязки, сборщик и запросы истории |
| `handlers/api/valueclouds.go` | HTTP API, доступ, представления станции и инвертора, агрегация |

## Протокол поставщика

Используется web API на `https://api.valueclouds.com`, включая
`POST /ppr/web/login/login`. Поле `password` содержит SHA-1 пароля в lowercase hex;
`project` равно `IOT`. Это отдельный профиль от мобильного API
`/ppr/app/login/pub/login`: пути не заменяются автоматически.

В ответе входа нужны `token`, `secret`; `Auth` читается из тела или заголовка
ответа. ID пользователя поддерживает числовую и строковую формы `userId`,
а также поле `uid`. Авторизованные запросы отправляют `token`, `Auth`,
`sign = HMAC-SHA256(secret, path)` в lowercase hex. Подписывается путь
с начальным `/` без query string. Заголовок `Auth` обновляется из ответов.
Пароль, его хеш и сессия не возвращаются клиенту приложения.

Клиент принимает коды `0` и `200`, а также `success=true` без кода.
Явный `success=false` и ошибочный код отклоняются даже при противоречивом
признаке успеха. Неуспешный HTTP статус обрабатывается до JSON, поэтому
HTML ответ HTTP 401 также распознаётся как ошибка авторизации.
Редиректы запрещены; максимальный размер ответа — 8 МиБ.

При HTTP 401 либо кодах `4`, `35`, `303` успешного HTTP ответа клиент
сбрасывает сессию. Для известных запросов чтения разрешены один повторный
вход и один повтор запроса. POST чтения проектов входит в этот список.
Неизвестные операции, POST записи и legacy GET управления не повторяются.
Ошибки соединения, HTTP 429 и 5xx автоматически не повторяются.

## Маршруты ValueClouds

Это маршруты, используемые Go-клиентом; их доступность зависит от аккаунта
и устройства. Они отличаются от API самого AtaEnergo в следующем разделе.

| Метод | Путь |
|---|---|
| POST | `/ppr/web/login/login` |
| GET | `/ppr/web/iotSysUser/auth/getInfo` |
| POST | `/dgm/api/dgm/itemseybond/getInfoByParams` |
| GET | `/dev/api/auth/valueCloud/dev/listTDeviceInfo` |
| GET | `/dev/api/auth/valueCloud/dev/singleDeviceInfo` |
| GET | `/ppe/api/auth/web/querySPDeviceLastData` |
| GET | `/ppe/api/auth/web/queryDeviceEnergyFlow` |
| GET | `/ppe/api/auth/web/queryDevicePars` |
| GET | `/ppe/api/auth/web/queryDeviceChartsFields` |
| GET | `/alm/api/auth/web/device/warnings` |
| GET | `/dcs/api/auth/web/ess/device/outputPowerOneDay` |
| GET | `/dcs/api/auth/web/ess/device/energyMonthPerDay` |
| GET | `/dcs/api/auth/web/ess/device/energyYearPerMonth` |

Устройство адресуется набором `pn`, `sn`, `devcode`, `devaddr`. Каталог проверяет
обязательные поля, дубликаты и полноту страниц. Отсутствующий массив устройств
или проектов считается ошибкой, а не пустым каталогом, который можно принять
за основание для архивации. Явный пустой массив является допустимым ответом.
Для устройств поддерживаются массивы `items`/`device`, числовой или строковый
`id`, числовые или строковые `devcode`, `devaddr`, `deviceStatus`.
Если `sn` отсутствует, используется `deviceSn`; PN вместо SN не подставляется.

Существующий ключ устройства остаётся `escape(pn):escape(sn):devaddr`.
`devcode` сохраняется отдельно в записи и отправляется поставщику. Повторение
ключа даже с другим `devcode` отклоняет неполный/неоднозначный каталог.
Статус без `deviceStatus` равен `-1` и не подтверждает онлайн. Поддерживаемые
коды соединения: `0` offline, `1` normal, `2` fault, `3` standby, `4` warning.

## API AtaEnergo

Требуется JWT приложения. Работа с аккаунтами доступна администратору;
маршруты CRM — сотрудникам с действующей связью объекта и аккаунта.
Внешний идентификатор станции и ключ устройства проверяются по её каталогу.

| Метод | Маршрут | Назначение |
|---|---|---|
| GET, POST | `/api/valueclouds/accounts` | Список и создание аккаунта |
| GET, PATCH, DELETE | `/api/valueclouds/accounts/{id}` | Получение, изменение и удаление аккаунта |
| POST | `/api/valueclouds/accounts/{id}/test` | Проверка входа |
| GET | `/api/valueclouds/accounts/{id}/devices` | Устройства для импорта |
| POST | `/api/valueclouds/accounts/{id}/import` | Импорт устройства в мониторинг |
| POST | `/api/crm/integrations/accounts/{id}/sync` | Обновление каталога |
| GET | `/api/crm/valueclouds/sites/{id}/telemetry` | Измерения и потоки станции |
| GET | `/api/crm/valueclouds/sites/{id}/devices/{device}` | Измерения, потоки, паспорт и параметры инвертора |
| GET | `/api/crm/valueclouds/sites/{id}/alerts` | Аварии станции |
| GET | `/api/crm/valueclouds/sites/{id}/devices/{device}/alerts` | Аварии инвертора |
| GET | `/api/crm/valueclouds/sites/{id}/history` | История станции, query `mode`, `date` |
| POST | `/api/crm/valueclouds/sites/{id}/devices/{device}/history` | История инвертора, JSON `mode`, `date` |

Создание аккаунта принимает `name`, `username`, `password` либо `password_sha1`.
Одновременная передача обоих вариантов пароля запрещена. Импорт принимает
`device_key`, `client` и необязательные `name`, `site`. Ключ устройства при
подстановке в URL необходимо кодировать как отдельный компонент пути.

## Телеметрия и время

`ReadSnapshot(ctx, device)` загружает последние показания и потоки энергии.
Отказ одного источника сохраняет результат второго и добавляет предупреждение.
Если оба запроса завершились ошибкой, возвращается ошибка. Отмена контекста
прерывает сбор без публикации частичного результата.

`Snapshot.Latest` хранит исходные группы и доступен даже для старых показаний.
`Snapshot.Payload` содержит только распознанную актуальную телеметрию и может
быть `nil`. `Snapshot.CollectedAt` — время завершения загрузки, не время
измерения. В API инвертора это поля `collected_at` и `live`; `live=true`
означает наличие допустимого текущего payload, а не успешность всех источников.

Время измерения берётся из `date` потоков или `gts` последних показаний.
Допускается Unix time в секундах и миллисекундах; `gts` также может быть строкой.
Данные старше 10 минут или более чем на минуту из будущего не поступают
в текущий мониторинг. Запись в БД использует время источника, повторный снимок
не продлевает связь и не создаёт повторных строк. Отсутствующие секции
ValueClouds не проходят общее заполнение нулями. Без времени измерения время загрузки не подставляется.
Для offline или неизвестного статуса текущий payload не публикуется.

Дополнительные значения объединяются с потоками только при разнице времён
не больше минуты. При отказе потоков свежие последние показания могут
самостоятельно дать payload. Число `0` сохраняется, пропуски не заменяются нулями.
Неизвестные идентификаторы доступны в сырых показаниях, но автоматически
не превращаются в нормализованные метрики.

| ID последних показаний | Группа | Нормализованное поле |
|---|---|---|
| `pv_output_power` | `pv_` | `pv[0].power`, Вт |
| `grid_active_power` | `gd_` | `grid.power`, Вт |
| `load_active_power` | `bc_` | `load.power`, Вт |
| `battery_active_power` | `bt_` | `battery.power`, Вт |
| `gd_rating_voltage` | `gd_` | `grid.voltage`, В |
| `bt_voltage_1` | `bt_` | `battery.voltage`, В |
| `bt_battery_current` | `bt_` | `battery.current`, А |
| `bt_battery_capacity` | `bt_` | `battery.soc`, % |

Для этих полей проверяются группа и единица; кВт переводятся в Вт, SOC
должен находиться в диапазоне 0–100. Идентификаторы конкретных моделей
расширяются только после проверки их смысла. Наличие измерений не создаёт
вымышленный признак отсутствия ошибок инвертора.

Суммы станции показываются только при наличии данных всех устройств
с разницей времён не более минуты. Даже тогда секция мощности отсутствует,
если её не предоставил хотя бы один инвертор. SOC нескольких аккумуляторов
не усредняется без данных об их ёмкостях. `lastUpdateTime` станции ограничен
самым старым из участвующих измерений.

## История

Режимы: `D` с датой `YYYY-MM-DD`, `M` с `YYYY-MM`, `Y` с `YYYY`,
`T` для доступных годовых рядов с момента создания устройства.
Дневные ряды содержат мощность в Вт, месячные и годовые — энергию в кВт·ч.
Часовой пояс исторических строк остаётся `Asia/Bishkek`.
Произвольная история всех регистров текущих показаний этим API не предоставляется.

Повторение одного поля на одном времени считается ошибкой. Неполные суммы
по устройствам и явные пропуски внутри годовой суммы возвращаются как `null`.
Полностью отсутствующий у поставщика месяц невозможно отличить от
отсутствующего периода работы; импорт полного архива требует отдельной сверки.

## Проверки

```bash
go test ./...
go test -race ./pkg/valueclouds ./services ./handlers/api
go vet ./...
```

Тесты используют локальный HTTP сервер и проверяют сессии, подписи, варианты
ответов, страницы каталога, частичные отказы, свежесть, единицы и агрегацию.
Они не заменяют проверку на реальном аккаунте. Схема БД, сохранённые пароли,
каталог и привязки импортированных модемов при этой переработке не мигрируют.
