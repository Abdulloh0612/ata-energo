# API Ата Энерго и Swagger

При стандартном запуске API находится по адресу `http://localhost:8000/api`. Откройте [Swagger UI](http://localhost:8000/swagger/index.html). Полный список методов, параметров и моделей доступен также в [Swagger JSON](swagger.json) и [Swagger YAML](swagger.yaml).

## Первый запрос с авторизацией

1. Откройте **Auth → POST /auth/login/**, нажмите **Try it out**, введите свой логин и пароль CRM в поля `username` и `password`, затем нажмите **Execute**.
2. Из ответа скопируйте значение `access`. Нажмите **Authorize**, найдите **BearerAuth** и введите слово `Bearer`, один пробел и сам токен.
3. Выполните **GET /me/**. В ответе появится профиль вошедшего пользователя. В строке Curl Swagger должен присутствовать заголовок `Authorization: Bearer …`.
4. Для списка аккаунтов Deye войдите под администратором CRM и выполните **GET /deye/accounts/**. Здесь `id` обозначает локальную запись аккаунта. Подключение к облаку проверяется отдельным запросом **POST /deye/accounts/{id}/test/**.

Swagger уже добавляет префикс `/api`. При вызове через другой HTTP-клиент укажите полный путь, например `GET /api/me/`. Когда срок действия `access` истечёт, отправьте `refresh` в `POST /api/auth/refresh/` и обновите значение в **Authorize**.

| Ответ | Что проверить |
|---|---|
| `400` | Прочитайте сообщение или ошибки отдельных полей. Сверьте тело запроса и обязательные параметры с моделью в Swagger. |
| `401` | Сообщение об отсутствии учётных данных означает пустой заголовок. При сообщении о неверном заголовке проверьте слово `Bearer` и пробел. Просроченный токен замените новым. |
| `403` | Проверьте роль CRM и право на операцию. Например, список пользователей доступен администратору и руководителю, а создание пользователя — администратору. |
| `404` | Проверьте путь и тип идентификатора. Для данных облака используются разные номера аккаунта, станции и локального модема. |

## Основные группы запросов

Все пути в таблице отсчитываются от `/api`.

| Раздел | Примеры запросов | Для чего нужен |
|---|---|---|
| Пользователи и клиенты | `GET /users/`, `POST /clients/`, `GET /clients/{id}/devices/` | Учётные записи, владельцы и состав оборудования |
| Мониторинг | `GET /modems/`, `GET /devices/{id}/history/`, `GET /alerts/` | Подключения, история показаний и события |
| Работа сотрудников | `GET /crm/requests`, `GET /crm/tasks`, `GET /crm/activity` | Заявки, задачи и журнал в пределах прав роли |
| Личный кабинет | `GET /my/devices/`, `GET /my/telemetry/`, `POST /my/requests` | Данные и обращения клиента |
| Облачные станции | `GET /deye/accounts/{id}/stations/`, `POST /deye/accounts/{id}/import/` | Просмотр станций облака и привязка инвертора к клиенту |
| Данные Deye по модему | `GET /modems/{id}/deye/latest/`, `POST /modems/{id}/deye/history/` | Последние измерения и история. Здесь нужен локальный ID импортированного модема. |
| Управление Deye | `POST /modems/{id}/deye/control/{command}/`, `GET /modems/{id}/deye/orders/{orderId}/` | Администратор отправляет команду устройству. Результат выполнения запрашивается отдельно по номеру заказа. |
| Поиск оборудования | `POST /agents/`, `POST /discovery/scan/`, `GET /discovery/tasks/{id}/` | Регистрация агента, выдача задания и проверка результата |
| Связь агента с CRM | `POST /agent/hello/`, `GET /agent/poll/`, `POST /agent/telemetry/` | Программа на объекте использует заголовок `X-Agent-Token` с токеном агента. |

## Показатели облачного объекта

`GET /api/crm/sites/{id}/telemetry` читает текущие мощности станции Deye, состав её оборудования и доступные измерения устройств. Используйте ID из `/api/crm/sites`, например `s223`. Маршрут доступен сотрудникам и работает для активной интеграции даже до назначения клиента. Ответ содержит `latest`, `flow`, `devices`, `readings` и `warnings`. Частично недоступные данные сопровождаются предупреждениями. Карточка объекта обновляет этот запрос каждые 3 минуты.

Для графиков карточка также использует `GET /api/crm/sites/{id}/history?mode=M&date=2026-11`. Режимы `D`, `M`, `Y`, `T` возвращают мощность за сутки, дневную энергию за месяц, месячную энергию за год и годовые итоги за срок работы станции. Формат даты зависит от режима. Будущие даты отклоняются. `GET /api/crm/sites/{id}/alerts` возвращает события за последние 30 дней. Самостоятельный пример дашборда доступен по `/station-dashboard.html`, его исходный файл — [station-dashboard.html](../web/public/station-dashboard.html).

## Обновления через WebSocket

Для локальной установки адрес подключения — `ws://localhost:8000/ws/telemetry/?token=<access>`. На HTTPS-домене используйте `wss://`. После подключения сервер отправляет `hello` с ролью и группами подписки. Сотрудники получают поток для сотрудников, клиент — события своей карточки.

| Тип сообщения | Содержимое |
|---|---|
| `telemetry` | Устройство и новые измерения |
| `status` или `modem` | Обновление состояния устройства или модема |
| `alert` | Событие оборудования |
| `pong` | Ответ на сообщение клиента `{"type":"ping"}` |

Код закрытия `4001` означает проблему с токеном, `4003` — у пользователя нет подходящей группы или привязки к клиенту. Регистрация маршрутов и обработка потока доступны в [коде сервера](../server/server.go) и [обработчике WebSocket](../handlers/ws/ws.go).

## Подробная карточка инвертора

Во вкладке оборудования станции нажатие на инвертор открывает `/sites/{id}?inverter={deviceId}`. Для облачного оборудования здесь используется ID устройства OpenAPI из списка этой станции. Возврат ведёт к вкладке оборудования.

- `GET /api/crm/sites/{id}/devices/{device}` возвращает паспорт устройства, все доступные точки измерения и схему потоков по его показаниям.
- `POST /api/crm/sites/{id}/devices/{device}/history` принимает `mode`, `date`, `measurePoints`. Для суток используются выбранные измерения, для остальных периодов — энергетические поля истории Deye.
- `GET /api/crm/sites/{id}/devices/{device}/alerts` возвращает аварии этого устройства за 30 дней.

Эти запросы доступны сотрудникам. Сервер проверяет принадлежность инвертора выбранной станции перед обращением к его данным. Обновление выполняется каждые 180 секунд. Локальные инверторы открываются в том же интерфейсе и используют сохранённые показания и историю CRM.

История инвертора за сутки поддерживает до 150 выбранных параметров. Сервер разбивает запрос на группы по пять ключей (ограничение Deye `historyRaw`) и объединяет результаты по временной метке, сохраняя пропуски.
